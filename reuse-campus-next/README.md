# ReUse Campus — Next.js migration

Full migration of the original PHP + MySQL application to a modern **Next.js 16 (App Router) + TypeScript + Tailwind CSS + shadcn/ui + Prisma + Auth.js + Zod** stack. The existing MySQL database (`reuse_campus`) and all user data are preserved.

---

## What was preserved

- All 12 MySQL tables, relationships, indexes, enums and demo rows (Prisma schema was generated with `prisma db pull` — read-only introspection, **no destructive migration**).
- All features: public pages, marketplace search/filter/sort/grid+list, item detail with rule-based matching, auth (register/login/logout/forgot/reset/verify), profile, listing CRUD with multi-image upload, complete request workflow (send/accept/reject/cancel/complete/return confirmation), favorites, notifications, exchange history, reports, and the full admin panel (users, listings, reports, categories, messages, analytics).
- Brand identity: deep green palette, logo, tagline, original copy and SVG artwork.
- Rule-based matching (no AI claim).

## Stack

| Concern | Choice |
|---|---|
| Framework | Next.js 16 App Router, React 19, TypeScript |
| Styling | Tailwind CSS 4 + shadcn/ui (base-ui primitives) |
| Icons | lucide-react |
| Database | Existing MySQL via Prisma ORM |
| Auth | Auth.js v5 (JWT sessions, Credentials provider, bcryptjs) |
| Validation | Zod |
| Mutations | Server Actions (CSRF handled by Next.js origin checks) |
| Feedback | sonner toasts, route loading skeletons |

## Setup (XAMPP / local)

1. Start Apache and MySQL in XAMPP. Import `../reuse-campus/database/schema.sql` into phpMyAdmin if the `reuse_campus` database is empty.

2. Install dependencies:
   ```bash
   npm install
   ```

3. Create `.env` from the template and set your values:
   ```bash
   copy .env.example .env
   ```
   ```env
   DATABASE_URL="mysql://root@localhost:3306/reuse_campus"
   AUTH_SECRET="generate-with: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))""
   ```
   `AUTH_TRUST_HOST=true` is already set in the example.

4. Generate the Prisma client (schema already matches the DB):
   ```bash
   npx prisma generate
   ```

5. Run the app:
   ```bash
   npm run dev          # http://localhost:3000
   npm run build && npm start   # production
   ```

## Security notes

- Every Server Action re-authenticates and re-checks authorization/ownership.
- Zod validates all form input server-side; Prisma parameterizes every query.
- File uploads are validated by **magic bytes** (JPEG/PNG/GIF/WEBP, max 5 MB) and stored with random UUID names under `public/uploads/`.
- Passwords remain bcrypt hashes — existing hashes verify unchanged with `bcryptjs`.
- Student ID, email, phone and profile details are never rendered on public pages.
- Role checks run in `src/proxy.ts` and again in every protected layout/action.

## Verification performed

- `npx tsc --noEmit` — clean.
- `npm run build` — all 32 routes compiled.
- HTTP smoke tests: all public, student and admin pages returned 200; guests and wrong roles redirected.
- Browser UI tests: student/admin login, favorite toggle (DB row inserted), contact form (DB row inserted), listing creation with real image upload (DB row + file written), request creation (DB row inserted). All test rows were deleted afterwards.

## Migration notes / intentional changes

- PHP sessions → Auth.js JWT cookies (`SameSite=Lax`, HttpOnly).
- PHP `include`-based components → React Server/Client Components.
- Raw SQL with double-quoted literals → typed Prisma queries.
- Email verification links are logged server-side in demo mode (no SMTP configured), same as the PHP app.
- Next.js 16 calls the middleware file `proxy.ts`; it is used here for optimistic role redirects only (authorization is enforced again in layouts/actions).
